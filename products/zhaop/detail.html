JobRadar · 工程详解

一条职位采集主链，加一条并行的社区信号链。
两者共享同一套订阅匹配与推送出口，但各自熔断、各自限速、各自可观测。
下面按数据流顺序拆解每个环节的职责与边界。

Data Pipeline
主链 · 公开社招职位
01 / COLLECT

适配器采集

19 家公司配置、18 家验证启用；按域名 2.2s 限速，每日 21:00 起调度。

02 / DIFF

快照对比

与上一份快照逐条对照，产出 added / changed / removed / readded 四类事件。

03 / MATCH

订阅匹配

关键词、城市与全字段规则命中；按用户聚合，同一事件只推一次。

04 / NOTIFY

定向推送

PushPlus / 企业微信 / 日志，10 分钟窗口合并，失败重试 3 次。

05 / DIGEST

每日汇总

21:30 汇总当日事件与信号，结构化落入推送正文。

06 / VIEW

Web 查看分析

六页静态工作台直接由 FastAPI 托管，无需前端构建步骤。

并行链 · 社区信号（独立熔断，共享出口）
S1 / SOURCES

脉脉 / V2EX / 牛客

公开页与 Atom feed；V2EX 可选代理，仅影响该源。

S2 / ATTRIBUTE

别名归属

最长别名优先、单归属；排除平台名，短别名要求招聘语境。

S3 / GATES

双质量闸门

时效 ≤ 3 天、正文 ≥ 12 字；拒营销与纯链接，fail-closed。

S4 / EVENT

信号事件

可证明来源与时间；低置信评论写入 signal_review 隔离审阅。

Design Decisions
01信号宁缺毋滥：分类为 other 直接丢弃；每帖只归属一家公司，无法证明发布时间的帖子一律不进正式流。
02失败隔离：信号源有独立熔断与 last_run 记录；单源不可达不影响职位主链，牛客首页空壳也有界重试三次。
03前端零构建：生产前端从 Vue 源码切换为 FastAPI 直接托管的静态多页，避免 npm 与构建链带来的部署漂移。
04推送可验证：设置页测试按钮用当前未保存配置真实发送并落库，失败不记假成功，webhook 密钥在错误信息中脱敏。
